# AR-песочница для клиники

Сайт проекта: https://amirrchik22.github.io/ar-sandbox-clinic/ — одна короткая
страница о конструкции, устройствах и подключении, плюс 3D-модель на весь
экран по кнопке.

Интерактивная песочница для занятий с особенными детьми под контролем
специалиста. Датчик глубины измеряет рельеф песка, компьютер превращает высоты
в цветную карту с горизонталями, проектор возвращает карту на песок. Софт ведёт
сеансы, пишет видео и карту высот, строит отчёты специалисту и работает в
кабинете без настройщика.

Статус на 23.09.2026: рабочая версия есть и проверена живьём на Kinect v2.
Программа запускается двойным щелчком, находит датчик, держит 18 кадров в
секунду и поднимает пульт специалиста — см. раздел «Как запустить» ниже.
Дальше — режимы занятия, карточки детей и записи. План — `docs/roadmap.md`.

Решения заказчика от 22.09.2026: базовый датчик — Kinect v2 (Xbox One) на
фиксированном выносе 450 мм от стены (не над центром ящика — широкое поле v2
позволило вывести датчик из луча проектора, и узел крепления перестал зависеть
от размера короба); Kinect v1 остаётся только дешёвой альтернативой; компьютер
покупаем, поэтому требование к материнской плате — USB 3.0 на контроллере
Intel или Renesas; проектор среднего сегмента, крепление только к стене
(натяжной потолок не трогаем), быстрый отклик — приоритет.

Решение заказчика от 23.09.2026: ящик 1200 × 800 мм внутри, слой песка
180 мм (было 130) и борт 300 мм над дном (было 250) — свободный край борта
120 мм над песком и есть то, что держит песок внутри.

## Как запустить

Программа одна и та же на всех трёх системах. Она поднимает маленький веб-сервер:
пульт специалиста открывается в браузере телефона или планшета, а страница
проекции выводится на проектор вторым экраном. Ставить ничего заранее не нужно,
кроме Python — всё остальное запускалка делает сама при первом запуске.

### Адреса

| Что | Адрес |
|---|---|
| Пульт специалиста — телефон или планшет | `http://<адрес компьютера в сети>:8080/` |
| Пульт на самом компьютере | `http://localhost:8080/` |
| Страница проекции — её перетаскиваем на экран проектора и разворачиваем | `http://localhost:8080/projector` |

Точный адрес для телефона программа печатает в окне запуска, там же показывает
QR-код: навёл камеру — пульт открылся. Телефон должен быть в той же сети Wi-Fi,
что и компьютер. Пароля нет и не будет: защита в том, что пульт виден только
внутри сети клиники.

Остановить программу — Ctrl+C в её окне.

### macOS

1. Двойной щелчок по файлу `софт/запустить.command`.
2. Первый запуск дольше остальных: программа создаёт себе окружение и ставит
   библиотеки, на это нужен интернет — один раз.
3. Откроется окно Терминала с адресами, пульт откроется в браузере сам.

Если macOS говорит, что файл от неизвестного разработчика: правый щелчок по
файлу → «Открыть» → «Открыть» ещё раз. Это нужно один раз на компьютер.

Если файл не запускается вовсе, в Терминале:

```bash
chmod +x "софт/запустить.command"
```

Датчик работает через программу захвата — её надо собрать один раз:

```bash
cd софт && bash tools/build_grabber.sh
```

### Windows

1. Двойной щелчок по файлу `софт\tools\run.bat`.
2. Первый запуск дольше: создаётся окружение и ставятся библиотеки, нужен интернет.
3. Откроется чёрное окно с адресами, пульт откроется в браузере сам.

Что поставить заранее: **Python 3.11 или новее** с сайта python.org. При
установке обязательно поставьте галочку «Add python.exe to PATH» — без неё
`run.bat` Python не найдёт и так и напишет, что делать.

Датчик на Windows читается не так, как на Маке и Linux: программу захвата надо
собрать отдельно, по шагам — ниже в разделе «Датчик на Windows». Пока её нет,
программа всё равно запускается и показывает демо-рельеф: интерфейс, режимы и
проекцию посмотреть можно, настоящий песок — нет, и `run.bat` об этом честно
пишет при старте.

### Linux (Ubuntu)

```bash
cd софт
bash tools/run.sh                 # найти датчик сам, порт 8080
bash tools/run.sh --sensor fake   # показ без датчика, демо-рельеф
```

Что поставить заранее:

```bash
sudo apt install python3.12 python3.12-venv build-essential cmake git
```

Датчик — та же программа захвата, что и на Маке:

```bash
bash tools/build_grabber.sh
```

Чтобы датчик работал без прав администратора, один раз положить правило udev
из исходников libfreenect2:

```bash
sudo cp vendor/libfreenect2/platform/linux/udev/90-kinect2.rules /etc/udev/rules.d/
sudo udevadm control --reload-rules && sudo udevadm trigger
```

### Другой порт и показ без датчика

```bash
./.venv/bin/python -m sandbox.console --sensor fake --open   # демо-рельеф
./.venv/bin/python -m sandbox.console --port 9000            # если 8080 занят
```

Если порт занят другой копией программы, она это увидит и скажет об этом
по-русски, а не упадёт с непонятной ошибкой.

## Датчик на Windows

Программа захвата `build\kinect_grabber.exe` — это те же исходники
`tools/kinect_grabber.cpp`, что на Маке и Ubuntu, но собранные компилятором
Windows. Собрать нужно один раз на том компьютере, где будет стоять песочница.

Путей два. Первый — libfreenect2 с драйвером libusbK: ровно то, что уже
работает на Маке, исходники менять не надо. Второй — Kinect SDK 2.0 от
Microsoft: драйвер официальный, но программу захвата пришлось бы писать заново
под другой интерфейс, такого кода пока нет. Поэтому по шагам описан первый путь.

**Что поставить**

1. Visual Studio Community 2022 (бесплатная), при установке выбрать
   «Разработка классических приложений на C++».
2. CMake для Windows с cmake.org, при установке — «Add CMake to system PATH».
3. Git для Windows с git-scm.com.

**Драйвер датчика**

4. Скачать Zadig с zadig.akeo.ie — это одна программа, устанавливать не нужно.
5. Воткнуть Kinect v2 в прямой порт USB 3.0 и включить его блок питания в розетку.
6. Запустить Zadig от имени администратора, меню Options → List All Devices.
7. Выбрать в списке «Xbox NUI Sensor (Interface 0)», справа выбрать драйвер
   **libusbK** и нажать Replace Driver. Повторить для «Interface 1», если он есть.
8. Помните: у устройства может быть только один драйвер. После замены Kinect
   SDK 2.0 датчик уже не увидит. Вернуть штатный драйвер можно там же в Zadig.

**Сборка библиотеки**

9. Открыть «x64 Native Tools Command Prompt for VS 2022» из меню Пуск и выполнить
   (путь `C:\ar-sandbox\софт` замените на свой):

```bat
cd /d C:\ar-sandbox\софт
git clone --depth 1 https://github.com/OpenKinect/libfreenect2.git vendor\libfreenect2
cd vendor\libfreenect2
depends\install_allDeps.bat
cmake -S . -B build -G "Visual Studio 17 2022" -A x64 ^
  -DCMAKE_POLICY_VERSION_MINIMUM=3.5 -DBUILD_OPENNI2_DRIVER=OFF ^
  -DENABLE_CUDA=OFF -DBUILD_EXAMPLES=OFF
cmake --build build --config Release
```

**Сборка программы захвата**

10. В том же окне вернуться в папку `софт` и собрать:

```bat
cd /d C:\ar-sandbox\софт
if not exist build mkdir build
cl /std:c++14 /EHsc /O2 ^
   /I vendor\libfreenect2\include /I vendor\libfreenect2\build ^
   tools\kinect_grabber.cpp ^
   /Fe:build\kinect_grabber.exe ^
   /link /LIBPATH:vendor\libfreenect2\build\lib\Release freenect2.lib
```

11. Положить рядом с `build\kinect_grabber.exe` библиотеки, без которых он не
    запустится: `freenect2.dll` из `vendor\libfreenect2\build\bin\Release`,
    а также `libusb-1.0.dll` и `turbojpeg.dll` из `vendor\libfreenect2\depends`.
    Если их не хватает, Windows скажет об этом окном «Не найден файл DLL».

12. Проверить, что захват работает:

```bat
build\kinect_grabber.exe --frames 1 > nul
```

Программа напечатает пару служебных строк и завершится без ошибки — значит
датчик открывается. После этого `tools\run.bat` подхватит его сам.

**Что здесь не проверено.** Прогнать эти шаги на настоящей Windows пока не на
чем: они выписаны по документации libfreenect2 и по рабочей сборке на Маке.
Сам исходник `tools/kinect_grabber.cpp` к Windows подготовлен и проверен
глазами: запись кадров и паузы разведены по системам, а стандартный вывод
переводится в двоичный режим — без этого Windows подменяла бы внутри каждого
кадра байт `0A` на пару `0D 0A` и Python видел бы мусор вместо кадров.

## Если датчик не видно

При каждом запуске программа сама смотрит, как подключён датчик, и пишет об этом
в окне запуска простыми словами: найден ли он, воткнут напрямую или через
разветвитель, на полной ли скорости работает порт. Смотрит она там, где это
видно системе: на Маке — `ioreg`, на Linux — `/sys/bus/usb/devices`, на
Windows — PowerShell. Коротко, что делать:

| Что написано в окне | Что делать |
|---|---|
| Датчик не найден на шине USB | Воткнуть кабель датчика; у Kinect v2 ещё и блок питания в розетку — без него датчик не появляется вовсе. На адаптере должен гореть белый огонёк. |
| Датчик подключён через разветвитель | Переставить кабель прямо в порт на корпусе компьютера. Через хаб Kinect v2 не работает никогда: кадры через него не пролезают. |
| Порт работает на скорости USB 2.0 | Переставить в порт с синей серединкой или значком SS. Если все порты такие — нужна плата USB 3.0 на контроллере Intel или Renesas. |
| Программа захвата не собрана | Собрать один раз: на Маке и Ubuntu `bash tools/build_grabber.sh`, на Windows — раздел «Датчик на Windows». |
| Нужна калибровка | Разровнять песок и нажать на пульте «Запомнить ровный песок». Так бывает, когда датчик задели или песка досыпали: программа считает высоты от старого нуля, видит это и честно говорит вместо того, чтобы красить бессмыслицу. |

На Windows скорость порта программа померить не может — там это штатными
средствами не видно, и она об этом так и пишет, а заодно советует, что
посмотреть в Диспетчере устройств. Разветвитель на Windows она различает.

Программа запускается в любом случае: если датчика нет, она показывает
демо-рельеф, и интерфейс с проекцией можно смотреть без железа. Саму проверку
можно выключить ключом `--no-usb-check` или переменной `SANDBOX_SKIP_USB_CHECK=1`.

## Как работает цикл

```
   датчик глубины (ИК)          компьютер                      проектор
 ┌──────────────────┐   USB   ┌────────────────────────┐  HDMI  ┌───────────┐
 │ расстояние до    │ ──────▶ │ сервис датчика:        │ ─────▶ │ картинка  │
 │ каждой точки     │ 30 к/с  │  шум, руки, высота     │ 60 к/с │ на песок  │
 │ песка, мм        │         │ рендер:                │        └─────┬─────┘
 └──────────────────┘         │  палитра, горизонтали, │              │
          ▲                   │  вода, задания, калибр.│              ▼
          │                   │ рекордер: видео, карта │      ┌───────────────┐
          └───────────────────│  высот, скриншоты      │◀─────│ песок + руки  │
            видит рельеф,     │ консоль: планшет       │      │ ребёнка       │
            не видит проекцию └────────────────────────┘      └───────────────┘
```

Цель — не больше 150 мс от движения руки до перекраски (расчётный бюджет
130–190 мс с Kinect v2, раздел 3.10 в `docs/architecture.md`). Датчик работает в
инфракрасном свете, поэтому цветная проекция ему не мешает. Подробно и про
руки ребёнка — `docs/pipeline.md`.

## Состав комплекта

| Узел | Выбор |
|---|---|
| Датчик глубины | базовый: Kinect v2 (Xbox One) + адаптер Kinect Adapter — 512×424 точки, поле 70°×60°, дальность 0,5–4,5 м, USB 3.0 на контроллере Intel/Renesas (в порт напрямую, без хаба) и свой блок питания; ось на X = 450 мм от стены (не над центром ящика), Y = 0, 1,252 м над песком (1,45 м от пола), смотрит вертикально вниз; зона охвата 1,75×1,45 м (по глубине −273…+1173 мм от стены, вдоль стены ±876 мм), 3,4 мм на точку, шум по высоте ≈2 мм, задержка 60–70 мс; зона больше картинки проектора, поэтому размер ящика датчик не ограничивает и на положение датчика не влияет; драйверы libfreenect2 (Linux) или Kinect SDK 2.0 (Windows, этап 0). Дешёвая альтернатива: Kinect v1 (Xbox 360) — точка мельче (2,0 мм против 3,4), но высота шумнее (3 мм против 2) и ИК-сетка теряет крутые склоны и борта. Оба — через общий интерфейс `sandbox/sensors`; Orbbec / RealSense — только будущие аналоги |
| Проектор | средний сегмент: 3LCD или DLP, XGA 1024×768 или WXGA 1280×800, 3300–4000 лм, обычный объектив (отношение 1,3–1,6, зум), ручной фокус, HDMI, игровой режим; в паспорте разрешена установка объективом вниз (иначе зеркало 45°); объектив на 1,95 м от пола (1,752 м над песком), наклон 2,6°, рабочее проекционное отношение 1,41, картинка 1,24×0,93 м — на песке от стены до 910 мм, ящик глубиной 800 накрыт целиком; выход горячего воздуха не в натяжной потолок |
| Компьютер | покупаем (подходящего нет): обязательное требование — материнская плата с USB 3.0 на контроллере Intel или Renesas, датчик в порт напрямую, без хаба; 6–8 ядер, 16 ГБ, NVMe 2 ТБ, дискретная видеокарта с кодированием видео; на этапе 0 допустим Windows с Kinect SDK 2.0, рабочая система — Ubuntu 24.04 в режиме киоска |
| Ящик | внутри 1200×800 мм (решение 23.09), фанера 18 мм, борт 300 мм над дном; на полу вплотную к стене (зазор 20 мм под плинтус), длинной стороной вдоль стены; слой песка 180 мм (допустимо 150–200), поверхность песка 198 мм от пола, верх борта 318 мм от пола, песка нужно 173 л ≈ 259 кг; борт — самое главное, чтобы песок не сыпался: свободный край 120 мм над песком, кромку скруглить, внутренние швы промазать герметиком, углы усилить уголками; центр ящика 438 мм от стены — это характеристика самого ящика, положение датчика она больше не задаёт |
| Крепление | только к стене: рейка 40×40 на три анкера M8 (низ 1,30 м, верх 2,30 м) на Y = +300 мм от центра ящика, Г-образная консоль (продольная часть по Y = +300 до X = 450 мм, поперечина к Y = 0 на той же X = 450 мм), датчик под поперечиной на выносе 450 мм от стены (ось 1,45 м от пола, низ корпуса ≈ 1,42 м, запас до луча проектора 100 мм); узел от размера короба не зависит; проектор на универсальном кронштейне по центру со страховочным тросиком; натяжной потолок не ниже 2,35 м, к нему ничего не крепим; гипсокартон — в стойки каркаса, иначе напольная стойка 2 м |
| Консоль специалиста | любой планшет, браузер, локальная Wi-Fi |
| Питание и сеть | ИБП на ПК и адаптер датчика, одна кнопка включения; кабели в канале 40×25 по стене и 25×16 вдоль плинтуса — ничего ниже 1,3 м в зоне детей; сеть клиники только для резервных копий |

Полностью — `docs/hardware.md`, `docs/wall-placement.md` (расчёт и чертежи),
`docs/architecture.md` (раздел 4). Цен в репозитории нет.

## Структура репозитория

```
docs/                 сайт проекта (index.html — коротко о главном, 3d.html — модель на весь
                      экран) и рабочие записи в markdown: архитектура, план софта, железо,
                      размещение у стены, цикл, план работ
sandbox/              пакет Python
  sensors/            интерфейс датчика + реализации (fake, kinect2 — базовый, kinect1 — альтернатива; orbbec — будущий аналог)
  depth_service/      фильтры, отсечение рук, калибровка, публикация кадров
  render/             рендер на видеокарте: шейдеры, палитры, ограничитель мерцания
  recorder/           запись: карта высот (.hmz), видео через ffmpeg, скриншоты
  console/            веб-консоль специалиста (FastAPI)
  supervisor/         наблюдатель: запуск, здоровье, перезапуски
  common/             конфиг, обмен между процессами, схема БД
config/               настройки, пресеты режимов, профили калибровки (не в git)
deploy/               systemd-юниты, настройка киоска Ubuntu
tests/                автотесты (работают без железа на FakeSensor)
tools/                запускалки (run.sh для Linux, run.bat для Windows; на Маке — запустить.command
                      в корне), сборка программы захвата build_grabber.sh и её исходник
                      kinect_grabber.cpp, запись и проигрывание кадров, чертёж размещения у стены
```

## Быстрый старт для разработчика (без железа)

```bash
cd софт
python3 -m venv .venv
./.venv/bin/pip install -r requirements.txt        # тот же список, что ставят запускалки
./.venv/bin/python -m sandbox.console --sensor fake --open   # пульт и проекция на демо-рельефе
./.venv/bin/python -m pytest -q                    # автотесты, железо не нужно
```

Запускалки (`запустить.command`, `tools/run.sh`, `tools/run.bat`) делают то же
самое и следят за списком библиотек: если `requirements.txt` изменился, они
переставляют библиотеки сами — сравнивают отпечаток файла с сохранённым в
`.venv/requirements-stamp.txt`. Версии в `pyproject.toml` повторяют тот же
список нижними границами, чтобы работал и `pip install -e ".[dev]"`.

С железом: `--sensor kinect2` — базовый датчик (Kinect v2 через libfreenect2
на Linux, Kinect SDK 2.0 на Windows); `--sensor kinect1` — дешёвая альтернатива
(Kinect v1 через libfreenect). Kinect v2 включать в порт USB 3.0 материнской
платы напрямую, без хаба; контроллер только Intel или Renesas.

`sensors/kinect2.py` и `sensors/kinect1.py` пока заготовки: датчик появляется в
реестре `sensors/__init__.py`, только если в системе установлен его драйвер, а
реальный захват кадров делаем на этапе 1. Без железа работает `fake`.
