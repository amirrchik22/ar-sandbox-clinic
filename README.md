# AR-песочница для клиники

Интерактивная песочница для занятий с особенными детьми под контролем
специалиста. Датчик глубины измеряет рельеф песка, компьютер превращает высоты
в цветную карту с горизонталями, проектор возвращает карту на песок. Софт ведёт
сеансы, пишет видео и карту высот, строит отчёты специалисту и работает в
кабинете без настройщика.

Статус: проектирование и скелет кода. Рабочей версии нет. Ближайший шаг —
этап 0: проверка железа на Magic Sand за неделю (`docs/software-plan.md`).
План — `docs/roadmap.md`.

Решения заказчика от 22.09.2026: базовый датчик — Kinect v2 (Xbox One) на
фиксированном выносе 450 мм от стены (не над центром ящика — широкое поле v2
позволило вывести датчик из луча проектора, и узел крепления перестал зависеть
от размера короба); Kinect v1 остаётся только дешёвой альтернативой; компьютер
покупаем, поэтому требование к материнской плате — USB 3.0 на контроллере
Intel или Renesas; проектор среднего сегмента, крепление только к стене
(натяжной потолок не трогаем), быстрый отклик — приоритет.

## Как работает цикл

```
   датчик глубины (ИК)          компьютер                      проектор
 ┌──────────────────┐   USB   ┌────────────────────────┐  HDMI  ┌───────────┐
 │ расстояние до    │ ──────▶ │ сервис датчика:        │ ─────▶ │ картинка  │
 │ каждой точки     │ 30 к/с  │  шум, руки, высота     │ 60 к/с │ на песок  │
 │ песка, мм        │         │ рендер:                │        └─────┬─────┘
 └──────────────────┘         │  палитра, горизонтали, │              │
          ▲                   │  вода, задания, калибр.│              ▼
          │                   │ рекордер: видео, карта │      ┌───────────────┐
          └───────────────────│  высот, скриншоты      │◀─────│ песок + руки  │
            видит рельеф,     │ консоль: планшет       │      │ ребёнка       │
            не видит проекцию └────────────────────────┘      └───────────────┘
```

Цель — не больше 150 мс от движения руки до перекраски (расчётный бюджет
130–190 мс с Kinect v2, раздел 3.10 в `docs/architecture.md`). Датчик работает в
инфракрасном свете, поэтому цветная проекция ему не мешает. Подробно и про
руки ребёнка — `docs/pipeline.md`.

## Состав комплекта

| Узел | Выбор |
|---|---|
| Датчик глубины | базовый: Kinect v2 (Xbox One) + адаптер Kinect Adapter — 512×424 точки, поле 70°×60°, дальность 0,5–4,5 м, USB 3.0 на контроллере Intel/Renesas (в порт напрямую, без хаба) и свой блок питания; ось на X = 450 мм от стены (не над центром ящика), Y = 0, 1,30 м над песком (1,45 м от пола), смотрит вертикально вниз; зона охвата 1,82×1,50 м (по глубине −300…+1200 мм от стены, вдоль стены ±910 мм), 3,6 мм на точку, шум по высоте ≈2 мм, задержка 60–70 мс; зона больше картинки проектора, поэтому размер ящика датчик не ограничивает и на положение датчика не влияет; драйверы libfreenect2 (Linux) или Kinect SDK 2.0 (Windows, этап 0). Дешёвая альтернатива: Kinect v1 (Xbox 360) — точка мельче (2,0 мм против 3,6), но высота шумнее (3 мм против 2) и ИК-сетка теряет крутые склоны и борта. Оба — через общий интерфейс `sandbox/sensors`; Orbbec / RealSense — только будущие аналоги |
| Проектор | средний сегмент: 3LCD или DLP, XGA 1024×768 или WXGA 1280×800, 3300–4000 лм, обычный объектив (отношение 1,3–1,6, зум), ручной фокус, HDMI, игровой режим; в паспорте разрешена установка объективом вниз (иначе зеркало 45°); объектив на 1,95 м от пола, картинка 1,2×0,9 м; выход горячего воздуха не в натяжной потолок |
| Компьютер | покупаем (подходящего нет): обязательное требование — материнская плата с USB 3.0 на контроллере Intel или Renesas, датчик в порт напрямую, без хаба; 6–8 ядер, 16 ГБ, NVMe 2 ТБ, дискретная видеокарта с кодированием видео; на этапе 0 допустим Windows с Kinect SDK 2.0, рабочая система — Ubuntu 24.04 в режиме киоска |
| Ящик | внутри 1000×750 мм (рекомендуем глубину 600), фанера 18 мм, борт 250 мм; на полу вплотную к стене (зазор 20 мм под плинтус), длинной стороной вдоль стены; песок 150 мм от пола; центр ящика 413 мм от стены (для 600 — 338) — это характеристика самого ящика, положение датчика она больше не задаёт |
| Крепление | только к стене: рейка 40×40 на три анкера M8 (низ 1,30 м, верх 2,30 м) на Y = +300 мм от центра ящика, Г-образная консоль (продольная часть по Y = +300 до X = 450 мм, поперечина к Y = 0 на той же X = 450 мм), датчик под поперечиной на выносе 450 мм от стены (ось 1,45 м от пола, низ корпуса ≈ 1,42 м, запас до луча проектора 114 мм); узел от размера короба не зависит; проектор на универсальном кронштейне по центру со страховочным тросиком; натяжной потолок не ниже 2,35 м, к нему ничего не крепим; гипсокартон — в стойки каркаса, иначе напольная стойка 2 м |
| Консоль специалиста | любой планшет, браузер, локальная Wi-Fi |
| Питание и сеть | ИБП на ПК и адаптер датчика, одна кнопка включения; кабели в канале 40×25 по стене и 25×16 вдоль плинтуса — ничего ниже 1,3 м в зоне детей; сеть клиники только для резервных копий |

Полностью — `docs/hardware.md`, `docs/wall-placement.md` (расчёт и чертежи),
`docs/architecture.md` (раздел 4). Цен в репозитории нет.

## Структура репозитория

```
docs/                 документы: архитектура, план софта, железо, размещение у стены, цикл, план работ
sandbox/              пакет Python
  sensors/            интерфейс датчика + реализации (fake, kinect2 — базовый, kinect1 — альтернатива; orbbec — будущий аналог)
  depth_service/      фильтры, отсечение рук, калибровка, публикация кадров
  render/             рендер на видеокарте: шейдеры, палитры, ограничитель мерцания
  recorder/           запись: карта высот (.hmz), видео через ffmpeg, скриншоты
  console/            веб-консоль специалиста (FastAPI)
  supervisor/         наблюдатель: запуск, здоровье, перезапуски
  common/             конфиг, обмен между процессами, схема БД
config/               настройки, пресеты режимов, профили калибровки (не в git)
deploy/               systemd-юниты, настройка киоска Ubuntu
tests/                автотесты (работают без железа на FakeSensor)
tools/                утилиты: запись и проигрывание кадров датчика, чертёж размещения у стены
```

## Быстрый старт для разработчика (без железа)

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
python -m sandbox.depth_service --sensor fake      # цикл датчика на синтетическом песке
pytest                                             # фильтры, руки, формат записи
```

С железом: `--sensor kinect2` — базовый датчик (Kinect v2 через libfreenect2
на Linux, Kinect SDK 2.0 на Windows); `--sensor kinect1` — дешёвая альтернатива
(Kinect v1 через libfreenect). Kinect v2 включать в порт USB 3.0 материнской
платы напрямую, без хаба; контроллер только Intel или Renesas.

`sensors/kinect2.py` и `sensors/kinect1.py` пока заготовки: датчик появляется в
реестре `sensors/__init__.py`, только если в системе установлен его драйвер, а
реальный захват кадров делаем на этапе 1. Без железа работает `fake`.

## Документы

- `docs/software-plan.md` — план программного обеспечения понятным языком:
  первая неделя на Magic Sand, проверка задержки, этапы 1–3, компьютер,
  настройки проектора, чек-лист первого запуска.
- `docs/architecture.md` — полный проект системы: режимы под группы детей,
  сеансы и запись, процессы, стек, датчики (3.3), бюджет задержки (3.10),
  калибровка, схема БД, железо и крепление (4), надёжность, данные и право.
- `docs/pipeline.md` — как работает цикл и что делать с руками ребёнка.
- `docs/hardware.md` — комплектация и требования совместимости.
- `docs/wall-placement.md` — размещение у стены: расчёт расстояний, узел
  крепления, кабели, чертежи в `docs/img/`, 3D-проверка `docs/wall-layout-3d.html`.
- `docs/mounting.md` — обзор вариантов крепления; стойка и потолок для этого
  объекта не применимы, наш случай — стена.
- `docs/roadmap.md` — этапы и критерии готовности, включая этап 0 (Magic Sand).

## Правила репозитория

- Цен нет ни в коде, ни в документах.
- Имён детей нет нигде: в коде, тестах, примерах, данных. Только коды вида `К-017`.
- Папки `data/` и `config/profiles/` не попадают в git.
- Никаких заявлений о лечении и диагностике. Формулировка продукта: «оборудование
  и ПО для развивающих и коррекционных занятий под контролем специалиста».
- Открытый код только с лицензиями MIT, BSD, Apache. GPL (SARndbox, Vrui) — нет.
